# DNS Latency Monitor — 画面デザイン案（バリエーション）

日付: 2026-07-25  
前提: いずれも **現行 UI を継承しないゼロベース**。共通で満たす機能だけ固定する。

## 共通機能（どの案でも必須）

| ID | 機能 |
|----|------|
| F1 | レイテンシ時系列グラフ（サーバー別）— **常に主役** |
| F2 | 表示範囲（窓の幅: 30m〜3d） |
| F3 | 履歴パン（窓の位置・履歴が長いとき） |
| F4 | 表示窓の統計（測定数・平均・P95・最大） |
| F5 | エラー種別内訳 |
| F6 | Uptime |
| F7 | データ鮮度 / 読込エラー |

共通意味論:

- 表示範囲 = グラフ横幅が表す時間  
- パン = その幅の窓を履歴上でずらす  
- F4–F6 は **いまの窓** に連動  

---

## 案 A — スタジオ（操作室 / モニター）

**ひとことで:** 左が操作と要約、右が広いグラフ面。

```
┌─────────┬──────────────────────────┐
│ 名称    │                          │
│ 鮮度    │        時系列グラフ       │
│ 範囲▼  │        （最大面積）        │
│ 統計    │        パン              │
│ Uptime  │  エラー帯                │
└─────────┴──────────────────────────┘
```

| 向いている | 向かない |
|------------|----------|
| PC でグラフ幅を最大化したい | 狭い画面（モバイルは縦に組替え） |
| 操作とデータを空間で分けたい | 左右分割を嫌う人 |

モバイル: グラフ → 範囲 → 統計 → エラー。

**現状ブランチの `studio` 実装は案 A に近い。**

---

## 案 B — シネマ（全幅キャンバス + 下ドック）

**ひとことで:** 画面ほぼ全体がグラフ。操作と要約は下の薄いドックに集約。

```
┌────────────────────────────────────┐
│  DNS Latency              鮮度     │  ← 極薄トップ
│ ┌────────────────────────────────┐ │
│ │                                │ │
│ │         時系列グラフ            │ │  ← ほぼ全面
│ │                                │ │
│ └────────────────────────────────┘ │
│ パン（必要時）                      │
│ ┌────────────────────────────────┐ │
│ │ 30m 1h … │ n avg p95 max │ up │ │  ← ドック
│ │ ████ エラー帯 ████             │ │
│ └────────────────────────────────┘ │
└────────────────────────────────────┘
```

| 向いている | 向かない |
|------------|----------|
| 「グラフを見に来た」用途がほぼ 100% | 統計を大きく読みたい |
| プレゼン・常時表示モニタ | 操作を左側に置きたい |

差別化: 案 A の左レールを廃止し、**視線は常に中央のプロット**。

---

## 案 C — マップ + 詳細（二重時間軸）

**ひとことで:** 上に全履歴のミニマップ、下に選択窓の詳細グラフ。

```
┌────────────────────────────────────┐
│ 名称 · 範囲 · 鮮度                 │
│ ┌────────────────────────────────┐ │
│ │ ░░░全履歴ミニマップ░░[窓]░░░░  │ │  ← パンはここで行う
│ └────────────────────────────────┘ │
│ ┌────────────────────────────────┐ │
│ │                                │ │
│ │     詳細グラフ（選択窓）        │ │
│ │                                │ │
│ └────────────────────────────────┘ │
│ 統計  n · avg · p95 · max   up     │
│ ████ エラー帯 ████                 │
└────────────────────────────────────┐
```

| 向いている | 向かない |
|------------|----------|
| 履歴が長く「今どこを見ているか」を明示したい | 実装コスト・描画負荷を抑えたい |
| パンの発見性を最大化 | 縦スペースが極端に少ない端末 |

差別化: スクロールバーではなく **時間軸の地図** がパン UI。窓の位置が一目で分かる。

---

## 案 D — ダッシュボード・タイル（指標とグラフの同居）

**ひとことで:** 上段に大きな数値タイル、下段にワイドグラフ（監視壁向け）。

```
┌──────────┬──────────┬──────────┬──────────┐
│ 平均     │ P95      │ 最大     │ Uptime   │
│ 225 ms   │ 291 ms   │ 329 ms   │ 98.2%    │
└──────────┴──────────┴──────────┴──────────┘
┌────────────────────────────────────────────┐
│  範囲 [30m…]                    鮮度       │
│  時系列グラフ（幅いっぱい）                 │
│  パン                                      │
└────────────────────────────────────────────┐
│  エラー帯                                  │
└────────────────────────────────────────────┘
```

| 向いている | 向かない |
|------------|----------|
| 数値の「今どう？」を先に知りたい | グラフ絶対主義（タイルが先に目に入る） |
| NOC / 壁掛けモニタ | モバイル縦スクロールを短くしたい |

差別化: 案 B と逆で **要約が上・グラフが下**。ただしタイルは 1 行に留め、グラフ面積は確保する。

---

## 案 E — フォーカス・シート（1 カラム・読み物寄り）

**ひとことで:** 記事のような 1 カラム。余白多め、最大幅を抑えて読む。

```
        ┌──────────────────────┐
        │ DNS Latency          │
        │ 鮮度 · 範囲          │
        │                      │
        │  大きめグラフ        │
        │  パン                │
        │                      │
        │  統計（横 or 2×2）   │
        │  エラー帯            │
        └──────────────────────┘
              max-width ~720–800
```

| 向いている | 向かない |
|------------|----------|
| ノート PC・タブレットで落ち着いて見る | ウルトラワイドをグラフで埋めたい |
| 実装が単純 | 「監視コンソール」感 |

差別化: 全幅スタジオでもシネマでもなく、**中央に置いた 1 枚のシート**。

---

## 案 F — スプリット・ホライズン（上下二分割・比率固定）

**ひとことで:** 上がグラフ 2/3、下が「分析トレイ」（統計 + エラー + 範囲）。

```
┌────────────────────────────────────┐
│              グラフ                 │  ~65%
│              パン                   │
├────────────────────────────────────┤
│ 範囲  統計  Uptime                 │  ~35%
│ エラー帯（幅いっぱい）              │
└────────────────────────────────────┘
```

| 向いている | 向かない |
|------------|----------|
| グラフと分析を常に同時表示 | エラー帯がグラフから遠いと嫌 |
| デスクトップ固定レイアウト | モバイル（トレイが押し上げる） |

差別化: 左右（A）でも下ドック薄型（B）でもなく、**下半分が本格トレイ**。

## 推奨の進め方

1. 上から **2〜3 案** を選ぶ（例: B / C / D）  
2. 選んだ案だけワイヤーを固定し、**1 案ずつ**実装して本番と並べて見る  
3. 同時に 6 案実装するとまた「どれも中途半端」になりやすい  

### デフォルト提案（反対がなければ）

| 優先 | 案 | 理由 |
|------|-----|------|
| 1 | **B シネマ** | 主役＝グラフが最も明確。機能は下ドックに集約 |
| 2 | **C マップ** | パンと「窓」の関係が視覚的に一番わかりやすい |
| 3 | **D タイル** | 数値先読み派向けの明確な別解 |

案 A はすでに近い実装があるので、比較用ベースにできる。
