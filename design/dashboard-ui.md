# DNS Latency Monitor — 画面設計（スタジオ・レイアウト）

日付: 2026-07-25  
意図: **従来の「上から縦積みカード」を捨てる**。操作・要約を左、時系列を右の広いキャンバスに分ける。

## 必要な機能

| ID | 機能 |
|----|------|
| F1 | レイテンシ時系列（サーバー別） |
| F2 | 表示範囲（窓の幅） |
| F3 | 履歴パン（窓の位置・必要時） |
| F4 | 表示窓の統計（測定数・平均・P95・最大） |
| F5 | エラー種別内訳 |
| F6 | Uptime |
| F7 | データ鮮度 / 読込エラー |

## レイアウト概念

**スタジオ型:** 左がコントロールルーム、右がモニター。

### デスクトップ（幅 ≥ 900px）

```
┌──────────┬────────────────────────────────────┐
│ DNS      │                                    │
│ Latency  │         レイテンシ時系列             │
│          │         （画面の主面積）              │
│ 最終…    │                                    │
│          │         履歴パン（必要時）            │
│ 表示範囲 │                                    │
│  · 30m   ├────────────────────────────────────┤
│  · 1h    │  エラー組成帯（横長）                 │
│  · …     │                                    │
│          │                                    │
│ 統計     │                                    │
│  測定…   │                                    │
│  平均…   │                                    │
│  P95…    │                                    │
│  最大…   │                                    │
│  uptime  │                                    │
└──────────┴────────────────────────────────────┘
```

- 左レール幅: おおよそ 15–17rem（詰めすぎない）  
- 右: 縦いっぱいにグラフ、下にエラー帯  
- ページスクロールなし（高さが足りるとき）

### モバイル（幅 < 900px）

縦積みに戻すが順序は:

1. タイトル + 鮮度  
2. **グラフ（主）** + パン  
3. 表示範囲  
4. 統計  
5. エラー + uptime  

（狭い画面で左レールにするとグラフが細く潰れるため）

## 見た目の方針

- 背景は落ち着いたダーク。左レールだけ一段暗い or 境界線で区画  
- グラフ領域は大きな面。過度な枠装飾はしないが、触れるコントラストは確保  
- 表示範囲は左では縦リスト（デスクトップ）。モバイルでは横並び  
- 余白は「窮屈にしない」程度。目的は機能と視線誘導であり、余白削減ではない  

## データ意味

- 表示範囲 = グラフ横幅の時間  
- パン = その幅の窓を履歴上で移動  
- 統計・エラー・uptime = いまの窓のみ
