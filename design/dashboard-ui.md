# 画面設計: DNS レイテンシ・モニター（ゼロベース）

| | |
|--|--|
| 状態 | 設計のみ（実装前の合意用） |
| 日付 | 2026-07-25 |
| 製品 | 自宅回線 DNS 応答の監視結果を見る Web 画面 |
| 前提の捨て方 | **現行 UI のレイアウト・ラベル・配色・情報の出し方はすべて破棄**。残すのは「DNS 時系列データがある」という事実だけ |

---

## 1. 何のための画面か

### 1.1 ユーザーが来た理由

「いま（または直近）、自宅の DNS は遅いか・死んでいるか」を **グラフを一目見て** 判断したい。

### 1.2 この画面が答える問い（これ以外は答えない）

1. 直近のレイテンシはどのくらいで、サーバー間で差はあるか  
2. そのあいだに失敗（タイムアウト等）はどれくらい・どんな種類か  
3. もう少し長い時間軸に広げた／ずらしたとき、傾向はどうか  

### 1.3 明示的にやらないこと

- 設定・アラート・通知・認証  
- 自由ズーム／ブラシ選択／注釈／CSV 出力 UI  
- マーケティング向けの説明文・オンボーディング  
- 「画面の使い方」を教えるためのメタ UI（枠ラベル、複数の同義テキスト、看板）  

---

## 2. 設計原則（ここが最優先）

| # | 原則 | 不合格の例 |
|---|------|------------|
| P1 | **キャンバスが製品** — 画面の大部分はプロット領域。UI クロムは背景に溶ける | ヘッダー・カード・説明が先に目に入る |
| P2 | **ラベルは最小** — 見ただけで分かるものは書かない。書くなら一度だけ | 「レイテンシ推移」「表示窓」「履歴ナビ」が同時に並ぶ |
| P3 | **同じ意味を二度言わない** | 範囲ボタンと枠タグとチップとキャプションが全部「30m」 |
| P4 | **操作は見つかるが主張しない** | タイムコントロールがビビッドな枠・大見出しを持つ |
| P5 | **沈黙は機能** — 情報がない／操作不要なときは UI を出さない | パン不要なのに常時トラックと説明 |

**合否の感覚テスト:** 画面のスクリーンショットを 1 秒見たとき、指差す場所が **線のグラフ** であること。

## 3. 情報アーキテクチャ（何を、どの順で、どの強さで）

### 3.1 レイヤ

```
[ L0  環境 ]  ほぼ無地の暗い面。ブランド主張なし。
[ L1  データ ] レイテンシの時系列（唯一のヒーロー）
[ L2  読み取り補助 ] 軸・系列色・ホバー時の数値（データに付随）
[ L3  要約 ] いま見ている区間の 数値 4 つ + 失敗の横帯 + uptime
[ L4  操作 ] ズームプリセット / （必要なときだけ）時間軸のずらし
[ L5  状態 ] データ鮮度 or エラー（問題があるときだけ強調）
```

L1 の面積・コントラスト・位置が常に L3–L5 を上回る。

### 3.2 データの「窓」モデル（概念のみ・UI 表現は §5）

- 測定履歴は時間軸上のストリーム  
- ユーザーが見るのは常に **連続した有限の時間窓**  
- 「窓の幅」を変える操作と、「窓を時間軸上でスライドする」操作は別  
- 要約（数値・失敗内訳）は **常にその窓の中身だけ**  

これはドメインのモデルであり、枠や看板で説明する対象ではない。操作結果としてグラフが変わることで理解させる。

## 4. レイアウト骨格（ワイヤー・テキスト）

既存の「ヘッダー／セクション見出し／カード／フッター帯」構造は使わない。

### 4.1 単一ステージ（全ブレークポイント共通思想）

画面全体を **1 枚のステージ** とみなし、プロットがその中心を占める。

```
┌──────────────────────────────────────────────────────────┐
│  DNS          30m  1h  3h  6h  12h  24h  3d     · 状態  │  ← 高さ最小の帯（L4+L5）
│                                                          │
│     ┌────────────────────────────────────────────┐       │
│     │                                            │       │
│     │              時系列プロット                 │       │  ← 面積の大半（L1）
│     │              （軸・系列はここだけ）          │       │
│     │                                            │       │
│     └────────────────────────────────────────────┘       │
│     ░░░░░ スライド（条件付き・低背） ░░░░░               │  ← L4 条件付き
│                                                          │
│     540   225ms   291ms   329ms     up 98.2%             │  ← L3 一行
│     n     avg     p95     max                            │
│                                                          │
│     ████████ 失敗の組成（細い帯のみ） ████████           │  ← L3
└──────────────────────────────────────────────────────────┘
```

### 4.2 モバイル

- 同じ骨格を縦に積む  
- 第一ビューに **プロットの上半分以上** が入ること（タイトル帯は 1 行に圧縮）  
- 範囲プリセットは横スクロール可だが、枠付きセグメント群にしない（テキスト列）  

### 4.3 デスクトップ（広い・高い）

- ページ全体スクロール禁止  
- プロットが縦方向の残り高さを吸収  
- 失敗帯は固定の薄いストリップ（プロットを食い潰さない）  

### 4.4 明示的に捨てる構造

| 捨てる | 理由 |
|--------|------|
| 「レイテンシ推移」「エラー種別内訳」などのセクション H2 | 位置と形で役割は分かる |
| サブタイトル説明文 | README の仕事 |
| グラフを囲む二重のカード／ネオン枠 | データより枠が目立つ |
| サイドレール（指標専用カラム） | グラフ幅を奪う |
| Uptime ヒーロー数字 | 主役を奪う |
| 「表示窓」「履歴ナビ」などの教示 UI | P3/P5 違反 |

## 5. 各要素の仕様

### 5.1 時系列プロット（L1）— 唯一のヒーロー

- **何を描くか**  
  - DNS サーバーごとのレイテンシ（点または包絡）  
  - 失敗区間の視覚（既存のデータ意味を活かすが、見た目はプロット内に閉じる）  
- **占有**  
  - モバイル: おおよそビューポート高の 45–55% 以上  
  - デスクトップ: 残り高さの大半  
- **クロム**  
  - 背景はステージと同系か一段だけ違う。太い枠線・影・角のタグは付けない  
  - グリッドは低コントラスト  
  - 系列凡例はプロット内（Chart 標準位置）に最小限。外側の凡例バーは作らない  
- **ホバー**  
  - その時刻の数値だけ。説明文の段落は出さない  

### 5.2 ズームプリセット（L4）— 窓の「幅」

- **意味:** プロット横幅が表す時間の長さ  
- **見た目:** 画面上端の **テキスト列**（例: `30m  1h  3h …`）  
  - 外枠ボックスなし  
  - 選択中は色または下線の **ひとつの変化** のみ（塗りつぶしピル＋枠＋影は禁止）  
- **配置:** タイトルと同じ 1 行帯の右寄せ  
- **コピー:** ボタンに単位付き短いラベルのみ。キャプション「＝グラフ横幅」は置かない  

### 5.3 時間スライド（L4）— 窓の「位置」

- **出現条件:** 利用可能な履歴の長さ ＞ いまの窓幅 のときだけ  
- **見た目:** プロット直下の **低背トラック（おおよそ 16–20px）**  
  - 常設の「ナビ」パネル・見出し・フッター日時ラベルは付けない  
  - トラック上の「いまの窓」の位置は、薄いハイライト 1 つで足りる（大声のシアン枠は不可）  
- **操作:** 横スクロール／ドラッグ。操作するとプロットの X が動く（これがフィードバック）  

### 5.4 要約数字（L3）

- プロット下に **一行**  
- 形式案（実装時に詰め可）:  
  `n 540    avg 225    p95 291    max 329` （単位は avg/p95/max に小さく `ms`）  
- ラベルは小文字略号または極小。カード分割・縦積み KPI はしない  
- 対象は **現在の窓** のみ  

### 5.5 失敗の組成（L3）

- 見出しなし  
- 横一列の積み上げ帯のみ（高さはプロットの数分の一）  
- 帯上の短いラベルはデータが許す幅のときだけ  
- **uptime** は帯の右外に小さな `up 98.2%` 程度。色は良/不良で静かに変える（巨大数字にしない）  

### 5.6 状態（L5）

- 通常: 上端帯の右端に `最終 07/25 10:06` 程度の極小テキスト  
- 読込中: 同じ位置で点滅ドット 1 つ、または「…」  
- 失敗: その行だけ色を変え、短いエラー文字列。ページ全体を赤くしない  

### 5.7 タイトル

- 左上に `DNS` または `DNS Latency` の短いワードマークのみ  
- 長い正式名称＋説明サブコピーは置かない（タブ title / README に任せる）

## 6. 視覚トーン

| 項目 | 方針 |
|------|------|
| 背景 | ほぼ無地のダーク。放射グラデや装飾メッシュは使わない |
| アクセント | 1 色系統のみ（系列色はデータ用に別パレット可） |
| コントラスト | プロット上のデータが最も高い。UI 文字は一段落とす |
| 角・影 | 角は小さく、影は原則なし |
| モーション | 不要。あるなら prefers-reduced-motion で殺す |
| タイポ | UI は system。数値は等幅寄り。装飾フォントなし |

「ops コンソール風」「ガラスモーフィズム」「ダッシュボードカード群」はいずれも採用しない。

## 7. インタラクション一覧

| 操作 | 結果 |
|------|------|
| ズームプリセット | 窓幅変更 → プロット再スケール。既定は最新側に窓を置く |
| スライド | 窓位置変更 → プロット X 移動。要約・失敗帯も同じ窓 |
| ホバー（プロット） | その時刻の値 |
| リサイズ | プロットがスペースを埋める。ブレークポイントで軸密度のみ調整 |
| 定期再取得 | データ更新。窓は可能な限りユーザー位置を尊重（詳細は実装判断） |

キーボード: 範囲ボタンはフォーカス可能。スライドはポインタ主（将来強化可）。

## 8. アクセシビリティ（静けさと両立）

- 範囲は `role="group"` + 各ボタン `aria-pressed`  
- プロット canvas に短い `aria-label`  
- 状態は `role="status"`（うるさいライブリージョン連打はしない）  
- コントラスト: 本文 muted でも WCAG 的に破綻しない下限を守る  
- スキップリンクは 1 本（フォーカス時のみ可視）  

「aria のために目立つ枠を増やす」はしない。

---

## 9. 成功条件（レビュー用）

実装後、次を **現行本番 URL と並べて** 判定する。

1. **1 秒テスト:** 目が先に行くのはプロットか  
2. **うるささ:** 同じ意味のラベルが 2 回以上出ていないか  
3. **操作の発見性:** ズームは上端で見つかるか。履歴が長いときスライドが使えるか  
4. **正しさ:** 要約がプロットの窓と一致するか  
5. **密度:** デスクトップで主要情報が 1 画面に収まるか  
6. **差:** 「本番の色違いコピー」ではなく、骨格が §4 になっているか  

1 または 6 を満たさないものは差し戻し。

---

## 10. 実装への拘束（設計がコードに勝つ）

- 本ドキュメントが UI のソース・オブ・トゥルース  
- 既存 `index.html` / `style.css` / 表示用マークアップは **参照せず捨ててよい**  
- データ取得・集計・プロット幾何（パンの数学）は **別レイヤ** として再利用してよいが、DOM の見た目契約は本設計に合わせて新規定義する  
- 必須となる論理 ID は実装 PR で決めてよい。設計は ID 名に依存しない  

---

## Key Decisions

| 決定 | 理由 |
|------|------|
| キャンバス＝製品 | ユーザーの問いが時系列の形でしか答えられない |
| セクション見出しを全廃 | うるささの主因。位置で役割を示す |
| ズームはテキスト列、枠なし | 操作は残しつつ視覚重量を下げる |
| スライドは条件付き・低背・無見出し | 必要なときだけ現れ、教示 UI にしない |
| 要約は一行の数字 | KPI カードはヒーローを奪う |
| 失敗は見出しなしの帯 | 二次情報として面積を最小化 |
| 現行 UI を継承しない | 「再現して静かにする」は失敗パターンだった |

## Open Questions

実装前に決めるとよいが、**デフォルト案**を括弧内に示す。反対がなければその案で進める。

1. ワードマーク表記: `DNS` / `DNS Latency` / 現行英語フル名称？  
   → デフォルト: **`DNS Latency`**
2. 要約ラベル: 英語略号 `n avg p95 max` か 日本語 `測定 平均 …` か？  
   → デフォルト: **日本語短語（測定・平均・P95・最大）を極小表示**（略号は冷たい）
3. 系列色パレットを現行チャートから変えるか？  
   → デフォルト: **データ識別性を保つため色相は維持、UI クロムだけ再設計**

## 変更しないもの（ドメイン）

設計が触らない／壊さないもの:

- 測定データ形式と取得経路  
- 「窓内だけ統計」という意味論（正しさ）  
- サーバー別系列というデータ次元  

これらは **UI の再現** ではなく **問題領域の事実** である。
