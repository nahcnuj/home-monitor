# DNS Latency Monitor — 画面設計

最終更新: 2026-07-25  
対象: `dashboard/` 公開 UI（https://www.nahcnuj.work/home-monitor/）

## 1. 目的

自宅回線の **DNS 応答レイテンシの時系列** を、短時間で把握できるようにする。

### 非目的

- 分析ツールの全機能（自由ズーム、注釈、エクスポート UI）
- タイムスパン操作そのものを主役に見せること
- 装飾のためのカード・グラデーション・看板 UI

## 2. 情報の優先順位（視線）

| 順位 | 要素 | 役割 |
|------|------|------|
| **1（主役）** | レイテンシ推移グラフ | 帯・点・タイムアウト帯を読む |
| **2** | コンパクト統計 | 測定数 / 平均 / P95 / 最大（**表示中の時間窓のみ**） |
| **3** | エラー種別内訳 + Uptime | 失敗の内訳（同じく表示窓） |
| **4（操作）** | 表示範囲プリセット | グラフ横幅に載せる時間の長さ（ズーム） |
| **5（操作）** | 履歴パン | 履歴 ＞ 表示範囲のときだけ、窓を時間軸でずらす |

**判断基準:** 初見 2 秒でグラフに目が行くこと。操作 UI がグラフより目立つ設計は不合格。

## 3. 概念モデル

```
全履歴 ────────────────────────────────────────►
        [ 表示窓 = 選択した 30m / 1h / … ]
                 ▲
            いまのグラフ X 軸
```

- **表示範囲（30m〜3d）**  
  - 意味: **1 画面（グラフの横幅）が表す時間の長さ**  
  - 意味しない: データの削除・切り捨て（cutoff は別設定）
- **履歴パン**  
  - 履歴の長さ ＞ 表示範囲のときだけ出現  
  - グラフ本体は常に「表示窓」だけを描画し、パンで窓を移動  
- **統計・エラー**  
  - 常に **いまの表示窓** に連動（パンしても更新）

## 4. レイアウト

### モバイル（〜999px / 高さ制約あり）

```
┌─────────────────────────────┐
│ タイトル          [範囲…]   │  ← 1 行、控えめ
│ 最終データ …                │  ← ミュート 1 行
│ レイテンシ推移              │
│ ┌─────────────────────────┐ │
│ │                         │ │
│ │     グラフ（最大面積）   │ │  ← 第一ビューの主対象
│ │                         │ │
│ └─────────────────────────┘ │
│ ── パン（必要なときだけ）── │  ← 細いが掴める
│ 測定数 · 平均 · P95 · 最大  │
│ エラー内訳        Uptime    │
│ ████ エラー帯 ████          │
└─────────────────────────────┘
```

### デスクトップ（幅 ≥1000 かつ 高さ ≥600）

- ページスクロールなし。縦を **グラフが大半** を占める flex 配分。
- ヘッダー・ステータス・統計・エラーは縮み、グラフが伸びる。
- エラー帯は短く固定高さ。余白でグラフを圧迫しない。

## 5. ビジュアル方針

| 項目 | 方針 |
|------|------|
| トーン | 落ち着いたダーク。背景 `#0f1117` 系、サーフェス 1 段 |
| グラフ枠 | 控えめな border + 角丸。ネオン枠・「表示窓」看板は置かない |
| 範囲選択 | 小さなセグメント。アクティブはアクセント塗りつぶしのみ |
| 時間メタ | 必要なら **1 行・低コントラスト**（例: `30m · 07/25 10:00 – 10:30`） |
| 履歴パン | 高さ約 18–22px。必要なときだけ表示。薄いトラック + 掴めるスクロール |
| 統計 | グラフ直下のインライン。カードグリッドにしない |
| タイポ | 本文 system-ui。数値は tabular。看板用の巨大 Uptime は使わない |

## 6. インタラクション

1. 範囲プリセット変更 → ズーム再計算、最新側の表示窓へピン、統計再計算  
2. 履歴パン → X 窓移動、統計・エラー連動  
3. リサイズ → コンパクト/PC レイアウト切替時は目盛り密度を再構築  
4. データ再取得（30 分間隔）→ 再描画、最新窓へ

## 7. 成功条件

- [ ] 本番と並べて、**グラフの読みやすさが同等以上**
- [ ] タイム UI が「うるさい」と感じない（枠・説明文・複数ラベルの重複なし）
- [ ] 履歴が長いとき **パンが使えて分かる**
- [ ] 統計が「見えている窓」と一致する
- [ ] PC 1 画面に収まる（主要コンテンツの縦スクロール不要）

## 8. 実装メモ

- チャート計算・パン幾何（`charts/latency.ts` 等）は既存ロジックを維持してよい  
- DOM の必須 ID: `latencyChart`, `latencyChartContainer`, `latencyChartScroll`, `latencyChartInner`, `errorChart`, `statsGrid`, `uptimeBadge`, `rangeSelector`, `lastUpdated`, `latencyLegend`  
- 見た目・骨格（`index.html` / `style.css` / `ui.ts`）は本設計に合わせて **新規**
